## 0. 사극체 예시를 이 과업으로 옮기기

강의자료의 평가 요소는 "목표 스타일을 생성하는 모델"을 전제로 한다. 이 프로젝트의 과업은 리뷰 → JSON 추출이므로 아래처럼 옮긴다.

| 강의자료 | 이 프로젝트 |
| --- | --- |
| 목표 능력: 사극체가 나타나는가 | 리뷰에서 aspect · attribute · sentiment · evidence를 가이드라인대로 뽑는가 |
| Golden Test Set | Gold Test 115건 (`gold_split_v1`, Train과 장소가 겹치지 않음) |
| Style Adherence Rate = 성공 응답 수 ÷ 전체 | **과업 성공률** = 성공 리뷰 수 ÷ 전체 리뷰 (2절) |
| 기존 능력: 일반 QA | 추출 외 일반 지시 수행 능력 (3절) |
| Judge 기준 5개 | 추출 과업용으로 바꾼 5개 기준 (4절) |

## 1. 질문 1 · 학습은 안정적으로 되었는가

W&B는 쓰지 않았다 (`training.report_to: none`). 대신 `training/experiments/qlora_gold_v001/loss_history.csv`에 강의자료가 요구하는 네 지표가 step 10 간격으로 모두 남아 있다. 이 CSV로 판단한다.

| 지표 | 관측값 | 강의자료의 주의 신호 | 판정 |
| --- | --- | --- | --- |
| train/loss | 0.171 (step 10) → 0.012 (step 170). 최저 0.0098 (step 140) | 너무 빠른 0 수렴은 암기 가능성 | 정상. 0에 붙지 않았다 |
| eval/loss | epoch 1 0.0371 → epoch 2 **0.0353** → epoch 3 0.0374 | 상승 전환 시 과적합 | **가벼운 과적합 신호.** epoch 3에서 6% 올랐다 |
| grad_norm | 0.080 ~ 0.420 (17개 기록). 초반 0.42에서 0.08~0.16대로 안정 | 폭증, NaN, 0 근처 지속 | 정상. 스파이크 · NaN 없음. `max_grad_norm` 1.0에 닿은 기록도 없다 |
| learning_rate | 설정 그대로의 곡선 (아래) | 그래프 모양이 설정과 다름 | 정상 |

**learning_rate 확인 방법.** 설정은 peak 2e-4, cosine, warmup 3%, 전체 174 step이다. warmup은 ⌈0.03 × 174⌉ = 6 step이 된다. CSV의 learning_rate 17개는 `2e-4 × 0.5 × (1 + cos(π × (step − 7) / 168))`와 부동소수점 오차(1e-16) 안에서 일치한다. 즉 warmup 6 step 뒤 174 step에서 0이 되는 cosine 곡선이고, 기록된 step과 1 step 어긋난 것은 로그를 남기는 시점 차이로 보인다. 설정과 다른 모양은 없다. 계산에 쓴 일회성 스크립트는 코드에 넣지 않았다.

**한계.**

- eval/loss는 epoch마다 한 번씩, 점 3개뿐이다. 과적합이 epoch 2 중간부터 시작됐는지 epoch 3에서 시작됐는지는 구분할 수 없다. 다음 run에서는 `eval_strategy: steps`로 더 자주 재는 것을 고려한다.
- 마지막 epoch의 train loss(0.012)와 eval loss(0.037)는 약 3배 차이다. loss 값 자체가 작아 절대 차이는 크지 않다.
- CSV 마지막 줄(step 174 eval)이 두 번 기록돼 있다. 학습 뒤 최종 평가가 한 번 더 기록된 것으로 보이며 값은 같다.

**답:** 학습은 안정적이었다. 다만 epoch 3에서 eval loss가 올랐으므로, 기존 문서 7절의 계획대로 `checkpoint-116`(epoch 2)과 최종 어댑터를 Validation으로 비교해야 한다.

## 2. 질문 2 · 목표 능력이 실제로 생겼는가

### 2-1. 이미 충족한 것

- 학습에 없던 입력으로 검증: Gold Test 115건은 Train과 장소가 겹치지 않는다.
- 같은 질문 · 같은 생성 설정: 같은 prompt, greedy, `max_new_tokens` 768.
- 결과표: 기존 문서 2절에 전체 · 카테고리별 지표와 paired bootstrap 신뢰구간이 있다.

### 2-2. 과업 성공률

강의자료의 성공 기준은 "여러 조건을 **모두** 충족한 응답"이다. 이 프로젝트에서 가장 가까운 지표는 리뷰 완전 일치(`exact_review_match`)다.

| | Base | QLoRA |
| --- | ---: | ---: |
| 리뷰 완전 일치 (엄격) | 22.6% | **57.4%** |

그런데 이 지표는 evidence 구절이 글자까지 같아야 성공으로 친다. 가이드라인상 둘 다 허용되는 구절 경계 차이도 실패가 된다. 강의자료의 4개 기준에 맞춰 아래 **과업 성공 기준**을 제안한다. 한 리뷰가 네 조건을 모두 만족하면 성공이다.

| # | 조건 | 강의자료 기준과의 대응 |
| --- | --- | --- |
| 1 | JSON이 스키마와 허용값을 지킨다 | 형식 (종결어미에 해당하는 "출력 규칙") |
| 2 | aspect 집합이 정답과 같다 (FP · FN 없음) | 내용 |
| 3 | 짝지어진 모든 aspect의 attribute · sentiment가 정답과 같다 | 내용 |
| 4 | 모든 evidence가 원문 구절이고, 정답 구절과 겹침 F1이 기준값 이상이다 | 일관성 (근거에서 이탈하지 않음) |

조건 4의 기준값은 **겹침 F1 ≥ 0.5**로 정했다 (2026-09-29). 경계 차이는 허용하고, 다른 문장을 근거로 쓴 경우만 실패로 본다. 이 지표는 평가 코드에 `task_success_rate`로 들어갔고, 다음 run부터 metrics.json에 자동으로 기록된다 (`evaluation/metrics.py`의 `task_checks`).

**결과 (Gold Test 115건).** 저장된 예측을 `compare_predictions.py`로 다시 채점했다. 기존 지표는 metrics.json의 값과 모두 같게 나왔다.

| 지표 | Base | QLoRA | 차이 | 95% 신뢰구간 (paired bootstrap 2,000회) |
| --- | ---: | ---: | ---: | --- |
| **과업 성공률 (겹침 ≥ 0.5)** | 55.7% | **75.7%** | +20.0%p | [+10.4, +29.6]%p · 유의미 |
| 리뷰 완전 일치 (엄격) | 22.6% | 57.4% | +34.8%p | [+25.2, +44.3]%p · 유의미 |

| 카테고리 | Base | QLoRA |
| --- | ---: | ---: |
| 호텔 | 22/38 (57.9%) | 32/38 (84.2%) |
| 식당 | 22/39 (56.4%) | 27/39 (69.2%) |
| 관광지 | 20/38 (52.6%) | 28/38 (73.7%) |

- 엄격 기준보다 차이가 작은 이유: Base는 정답과 같은 곳을 가리키되 구절 경계를 다르게 잡는 경우가 많다. 엄격 기준은 이 경계 차이까지 실패로 센다.
- 정확 일치 기준(엄격)은 참고값으로 함께 보고한다.

### 2-3. 같은 리뷰, 다른 답변 (누락)

강의자료는 점수만이 아니라 **답변 원문과 판정 근거를 함께** 기록하라고 한다. 기존 문서에는 개별 사례가 없다. 두 run의 예측 파일을 `review_id`로 맞춰 아래 사례를 고른다.

| 사례 | 고르는 규칙 | 개수 |
| --- | --- | --- |
| 개선 | Base 실패 · QLoRA 성공 | 카테고리별 1건 |
| **퇴행** | Base 성공 · QLoRA 실패 | 있는 만큼 모두 |
| 둘 다 실패 | 둘 다 실패. 기존 문서 3-3절의 neutral 오류 포함 | 2~3건 |

퇴행 사례가 특히 중요하다. 평균이 올라도 Base가 맞히던 리뷰를 QLoRA가 틀리게 되었다면 그 유형을 따로 적어야 한다. 기존 문서에는 이 수치가 없다.

**결과.** 115건 중 개선 29 · **퇴행 6** · 둘 다 성공 58 · 둘 다 실패 22.

## 3. 질문 3 · 기존 능력은 유지되는가 (누락)

강의자료는 목표 능력이 좋아져도 기존 질문 응답 능력이 무너지면 좋은 파인튜닝으로 보지 않는다. 기존 문서에는 이 평가가 없다.

### 3-1. 이 프로젝트에서 이 질문이 갖는 의미

- 어댑터는 추출 과업에서만 불러온다. 추출만 할 때는 일반 능력이 떨어져도 서비스에 직접 영향이 없다.
- 하지만 같은 base 모델에 어댑터를 붙인 채 다른 과업(향후 일정 생성 등)에 쓸 가능성이 있다면 영향이 생긴다. 모든 입력을 JSON으로 답하려는 경향은 이 경우 드러난다.
- 기관 평가 틀이 이 항목을 요구하므로, 결과가 "영향 없음"이더라도 측정해서 기록한다.

### 3-2. 진행 방법 (강의자료 8쪽을 그대로 따름)

1. **일반 QA 세트 준비.** 추출과 무관한 한국어 질문 30~50개(상식 · 코딩 · 요약 · 짧은 대화), 또는 KMMLU 같은 공개 벤치마크의 일부. 어느 쪽을 쓸지는 정해야 한다 (8절).
2. **같은 조건으로 채점.** Base와 QLoRA에 같은 질문, 같은 생성 설정(greedy, 같은 `max_new_tokens`, `enable_thinking: false`)을 준다. 추출용 system prompt는 넣지 않는다. 객관식이면 정답률, 서술형이면 4절 Judge의 정확성 점수로 비교한다.
3. **허용 기준을 먼저 정한다.** 결과를 보기 전에 합의한다. 강의자료의 예는 "정답률 하락 3%p 이내면 유지"다. 이 프로젝트의 기준값은 아직 정하지 않았다 (8절).

### 3-3. 비교 조건 주의

기존 문서 4절처럼 Base는 16bit, QLoRA는 4bit다. 일반 능력이 떨어졌을 때 원인이 양자화인지 튜닝인지 구분하려면 **4bit Base**도 함께 잰다.

| 비교 | 보는 것 |
| --- | --- |
| 16bit Base vs 4bit Base | 양자화만의 영향 |
| 4bit Base vs QLoRA | 튜닝만의 영향 (허용 기준은 이 비교에 적용) |

추가로, 어댑터를 붙인 채 일반 질문에 JSON으로 답한 비율도 센다. 과업 형식이 다른 과업으로 새는지 보여주는 지표다.

## 4. 질문 4 · 사람이 보아도 좋은가 (누락)

### 4-1. Gold 채점이 있는데 Judge가 왜 필요한가

Gold 기반 지표는 정답과 다르면 무조건 틀린 것으로 친다. 그런데 기존 문서 3-3절의 neutral 오류처럼 정답과 달라도 리뷰를 보면 변호할 수 있는 판단이 있고, evidence 경계도 사람마다 조금 다르다. Judge와 사람 평가는 **정답이 아니라 리뷰 원문을 기준으로** 두 출력을 비교한다. 그래서 Gold 채점이 놓치는 것을 보완한다.

### 4-2. LLM-as-a-Judge

강의자료의 5개 기준을 추출 과업에 맞게 바꾼다. 모두 1~5점이다.

| 강의자료 기준 | 이 과업의 기준 | 보는 것 |
| --- | --- | --- |
| Correctness | 정확성 | aspect · attribute · sentiment가 리뷰 내용과 맞는가 |
| Relevance | 근거성 | evidence가 그 판단을 실제로 뒷받침하는가. 리뷰에 없는 aspect를 만들지 않았는가 |
| Instruction Following | 지시 준수 | 스키마 · 허용값 · 원문 그대로의 구절 |
| Style Adherence | 가이드라인 준수 | 사실만 말하면 neutral, 가장 짧은 구절, 주변 정보를 시설로 오해하지 않기 |
| Fluency | 활용성 | 이 출력을 Review Profile에 그대로 집계해도 되는가 |

지시 준수는 자동 검사(JSON 준수율, 허용값 위반)와 겹친다. Judge 점수와 자동 검사가 어긋나는지 보는 교차 확인용으로 둔다.

운영 절차 (강의자료 10쪽):

1. 한 프롬프트에 리뷰 원문, 가이드라인 요약, 답변 A · B, 루브릭을 넣고 기준별 점수와 근거를 JSON으로 받는다. **Gold는 넣지 않는다.** Gold와 독립된 판단이어야 보완이 된다.
2. A/B 순서를 바꿔 두 번 채점하고 평균한다. 두 번의 승자가 다른 비율(위치 편향)도 기록한다.
3. Judge 모델은 평가 대상과 다른 모델을 쓴다. Teacher와 평가 대상이 모두 Gemma4 E4B 계열이므로 Gemma 계열이 아닌 모델을 쓴다. temperature는 0으로 고정한다.
4. 두 출력이 글자까지 같은 리뷰는 Tie로 처리하고 Judge에 보내지 않는다.
5. 기준별 평균, 승률(QLoRA Win / Base Win / Tie)을 전체 · 카테고리별로 낸다.

> 외부 API를 Judge로 쓰면 리뷰 원문이 외부로 나간다. 실제 리뷰(번역본)를 보내도 되는지 먼저 확인한다.

### 4-3. Human Evaluation

- **대상:** 두 출력이 다른 리뷰 중 30~50건. 카테고리별로 고르게 뽑는다.
- **블라인드:** 모델 이름을 숨기고 A/B 순서를 리뷰마다 무작위로 섞는다.
- **질문 (강의자료 9쪽을 옮김):**
  - 어느 출력이 리뷰 내용을 더 정확히 담았는가?
  - 어느 출력이 Review Profile 목적에 더 적합한가?
  - 실제 서비스에 그대로 쓸 만한가?
  - 없는 내용을 지어내거나 어색한 근거 구절은 없는가?
- **결과:** QLoRA Win / Base Win / Tie. 평가자가 두 명 이상이면 평가자 간 일치율도 적는다.

## 부록. 용어

- **W&B (Weights & Biases):** 학습 중 loss, learning rate 같은 값을 실시간 그래프로 기록하는 실험 관리 도구.
- **grad_norm:** 한 번의 업데이트에서 계산된 기울기(gradient) 벡터의 크기. 갑자기 커지면 학습이 불안정하다는 신호다.
- **gradient clipping (`max_grad_norm`):** grad_norm이 정해진 값을 넘으면 그 값으로 줄여서 업데이트가 튀지 않게 하는 장치.
- **warmup · cosine decay:** 처음 몇 step은 learning rate를 0에서 목표값까지 올리고(warmup), 이후 코사인 곡선을 따라 0 근처까지 내리는(cosine decay) 스케줄.
- **과적합(overfitting):** 학습 데이터에만 맞춰져 처음 보는 데이터에서 성능이 떨어지는 현상. train loss는 내려가는데 eval loss가 오르면 의심한다.
- **회귀 평가(regression evaluation):** 새 학습 뒤에도 원래 되던 능력이 여전히 되는지 확인하는 평가.
- **KMMLU:** 한국어 지식 · 추론 능력을 객관식으로 재는 공개 벤치마크.
- **LLM-as-a-Judge:** 다른 LLM에게 루브릭을 주고 모델 출력을 채점하게 하는 방법.
- **위치 편향(position bias):** Judge가 먼저 제시된 답변을 더 좋게 평가하는 경향. A/B 순서를 바꿔 두 번 채점해 줄인다.
- **블라인드 평가:** 평가자가 어느 모델의 출력인지 모르게 하고 비교하는 방법.
- **평가자 간 일치율:** 여러 평가자가 같은 항목에 같은 판정을 내린 비율. 평가 기준이 명확한지 보여준다.
- **체크포인트(checkpoint):** 학습 중간에 저장한 모델(여기서는 어댑터) 상태.
