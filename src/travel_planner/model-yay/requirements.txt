# EXAONE-3.5-7.8B-Instruct는 trust_remote_code=True로 커스텀 모델링 코드(modeling_exaone.py,
# configuration_exaone.py, revision 553ea25 = HF의 main)를 함께 받는다. 이 코드는 transformers 5.0/5.1
# 시점의 내부 API를 그대로 부른다:
#   - RopeParameters (transformers.modeling_rope_utils): transformers 5.0에서 새로 생김 → transformers<5면
#     ImportError.
#   - create_causal_mask(input_embeds=...) (transformers.masking_utils): 이 키워드 인자 이름이 5.2.0부터
#     input_embeds → inputs_embeds로 바뀌었다 → transformers>=5.2면 TypeError: unexpected keyword
#     argument 'input_embeds'.
# 즉 이 원격 코드가 실제로 맞는 범위는 transformers 5.0.x~5.1.x뿐이다. transformers 5.17.0(팀원
# origin/lkh_train의 Gemma4 파이프라인이 쓰는 버전)에서는 뒤 문제가 난다. EXAONE 3.5는 transformers에
# 내장(model_type "exaone")돼 있지도 않다 — 5.17.0에는 exaone4/exaone4_5/exaone_moe만 있고 EXAONE 3.5의
# "exaone"은 없어서, trust_remote_code: false로는 못 돌린다 (config.yaml에 이 경위를 적어 뒀다).
#
# trl==1.14.0은 "transformers!=5.1.0"을 명시적으로 막아 놓았다 (알려진 transformers 버그,
# transformers#43780). 그래서 남는 선택지는 transformers==5.0.0 하나뿐이다. peft==0.21.0/
# accelerate==1.15.0/bitsandbytes==0.50.2는 팀원과 같은 버전을 그대로 두었다 — 이 조합으로
# `uv pip compile`이 충돌 없이 풀린다는 것까지는 확인했지만(설치 시점 메타데이터 검증), 팀원처럼
# transformers 5.17.0으로 실제 학습까지 검증된 조합은 아니다. 아래 확인 명령으로 config/tokenizer가
# 문제없이 열리는지, 학습 스모크(--max-steps)로 forward/backward가 실제로 도는지 반드시 먼저 본다.
#
# transformers 5는 TrainingArguments.warmup_ratio를 없애고 warmup_steps가 1 미만 실수면 비율로
# 취급하도록 바꿨다 (5.0.0부터 이미 이 규칙이다). config.yaml의 training.warmup_steps, train.py의
# build_sft_config 참고.
#
# 실제 설치 전에 팀 GPU 환경(CUDA 버전)에 맞는 torch를 먼저 설치하는 것을 권장한다.
